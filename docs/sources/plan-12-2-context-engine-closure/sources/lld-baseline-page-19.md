# 4A. Failure and retry lifecycle
Record the true failure, preserve receipts/effects and inject bounded failure context only when configured work limits permit another planning round. Keep count/time/repeated-failure controls distinct from provider attempts. The interim ACP defaults are three planning rounds, 30 minutes and two repeated failures. Product BudgetExhaustedError is retired by the accepted migration; independent evaluations may retain their scoped dollar stop.
The legacy host permits an initial attempt plus at most three retries. The inactive-policy Gateway separately permits at most three upstream attempts, including its legacy transient timeout/URL/5xx retries. Once enforcement is active, the Gateway permits one primary attempt and at most one identical-payload resend on the same route, only after a definitely NOT_SENT result (including a proven pre-connection timeout) or rejected HTTP 429. A timeout after connection, uncertain delivery, 5xx or unknown accounting is not resent. The host honors non-retryable classifications so it cannot multiply attempts. No alternative-model recovery is added. Each physical attempt retains its own receipt.

# 5. ADL parser continuity and architectural evolution
ADLParserStrategy retains parse_and_validate(adl_rules: list[str], proposed_diff: str) -> tuple[bool, list[dict]] as its abstract validation contract. PrototypeRegexADLParser retains the existing ASSERT(<a>) HAS NO DEPENDENCY ON <b> matching grammar, lowercases captured names for code import checks, and checks both an import <b> occurrence and the org.springframework.<b> substring in the diff. Violations retain rule, Structural Pollution metric and Violation: (<a> -> <b>) value. It returns true only when the violations list is empty. The regex implementation is a prototype and does not become a new semantic analyzer through this migration.
