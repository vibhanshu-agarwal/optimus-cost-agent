## Embedded contract

### A1. Owned progress, workers and failure reporting

1. Maintain an adapter-owned, bounded per-turn progress lane: at most one physical send executing and one newest pending progress event. Coalesce only a still-unsubmitted progress event; never reorder or rewrite a frame already submitted to the writer. At the final admission barrier, submit that one pending event behind the executing frame without awaiting its flush; retain at most those two completion records, retire the lane to new offers and drain physical completion later. The default observer still receives each original event once. Worker-to-loop handoff uses one lock-protected latest-event cell plus a wakeup-scheduled flag, at most one scheduled callback. The loop clears the flag before reading the cell. Contain call_soon_threadsafe RuntimeError when the loop is closed; increment a bounded counter, never raise into the planner. Scheduling one callback/coroutine per event would itself be an unbounded queue and is prohibited. Do not coalesce cost, permission, plan, response or settlement records.
2. Ordering is established at writer admission. After the planning `_in_worker` call returns or raises, the turn awaits `ProgressLane.settle()`. Settle completes when the lane has no unsubmitted event: every offered event has been coalesced, suppressed by TurnControl, or passed `DedicatedOutboundWriter.submit`. On the non-dedicated test path, settle waits for the awaited `write_line`. This happens before any further outbound frame of that turn, on every branch (Chat final text, completion messages, context-plan-too-large, plan update, permission, cost alerts, error and protocol responses). Physical completion remains owned by the lane's retained send and is drained at turn finalization or adapter shutdown. No flush wait, timeout or transport teardown is attached to best-effort progress. Take a TurnControl `try_start(SendKind.PROGRESS, …)` lease only for an event actually submitted; coalesced events create no QUEUED slot. Writer submission raising after close maps to SUPPRESSED inside the lane and never escapes into a callback.
3. Cancellation/EOF stops new progress, suppresses queued not-started sends and requests cancellation of the actual loop task. Keep the separate owner-side completion observable; cancelling the public future alone is not proof that its underlying coroutine/physical write stopped. Repeated cancellation joins the same owned lane. Late worker callbacks after retirement are no-ops with bounded counters, not new tasks or sends.
4. `_in_worker` keeps the existing invocation start/end/abandon-unstarted semantics and actual provider receipts. Retain a shielded task for every started `to_thread` job until the physical call returns; retrieve failures once. Prompt cancellation stays responsive, while shutdown owns the drain. An adapter-owned set retains lanes and started worker tasks, joined in `AcpDuplexAdapter.aclose` before writer close, like `_mcp_close_tasks`. Turn-finalization drains are shielded. No extra thread per callback, new executor or callback backlog.
5. F1: capture only an exception actually raised by this serving invocation using explicit except capture, not ambient `sys.exc_info()` in a clean finally. Test clean EOF awaited inside an unrelated caller exception handler.
6. F2: preserve the selected original exception instance, traceback and existing cause/context. Control-flow exceptions take precedence, then the first ordinary primary. All cleanup stages still run. Report secondary/tertiary failure visibility through one bounded `BaseException.add_note` using fixed stage codes and count, not raw exception messages or arbitrary class names. Do not overwrite an existing cause with `raise primary from secondary`. At most one stage note is attached per exception instance, including a CancelledError re-raised through two teardown layers. No ExceptionGroup/framework is introduced. The proposed successor decision record explicitly supersedes only ADR-027's sentence requiring a secondary cause chain, and the identical design sentence is updated; the frozen ADR remains unchanged.

### A2. One process-stop coordinator, explicit limits

- One CLI-owned `ProcessLifecycle` is installed after launch authorization and before owned startup for normal, framed and `--check-config` paths. RUNNING -> STOP_REQUESTED -> DRAINING -> COMPLETE; an INCOMPLETE observation does not change DRAINING into COMPLETE. First reason wins; repeated signals only increment a bounded count. No second teardown or forced-exit escalation.
- **Before a loop is bound**, the first owned SIGINT/POSIX SIGTERM handler latches the fixed reason and then raises a fixed control exception (KeyboardInterrupt for SIGINT; a dedicated BaseException subclass for SIGTERM). Preserve current synchronous-startup interruptibility, including Docker calls/readiness sleeps/build. Further signals during cleanup only count. No arbitrary exception text, resource locking, logging I/O or async work in handlers.
- **Once bound**, a signal only latches and uses `call_soon_threadsafe` to cancel the one serve task once. Install `signal.signal` handlers before entering `asyncio.Runner`; Runner sees a non-default SIGINT handler and installs/restores nothing. Restore exact prior handler identities after Runner exits, in a finally covering startup exceptions too. Windows uses `signal.signal`, never unsupported Proactor `add_signal_handler`. POSIX SIGTERM is catchable; Windows `Popen.terminate`/TerminateProcess is forced, not graceful SIGTERM evidence.
- Put Gateway acquisition under the CLI outer try/finally. In `ensure_local_gateway`, guard the complete post-Popen readiness phase with `except BaseException: LocalGatewayProcess(process, log_path).stop(); raise`. Retain its handle/cleanup outcome if stop itself fails, and preserve the initiating failure per the F2 rule. No ownership is claimed over shared Redis/Phoenix.
- **Recommended C2(b), proposed for operator acceptance:** replace default-executor physical stdin reads with one owned daemon reader thread for the real stdio adapter, started lazily and serving at most one outstanding read. This is not a pool; it never force-closes borrowed stdin, and retains the physical completion/outcome. The cancellation of an await is not physical completion. The thread may remain blocked and reported incomplete, but it does not pin interpreter exit. Framed and NDJSON real stdin share this policy; injected async/fake readers retain their explicit interfaces. Any handoff cell/command channel is finite (one pending read), not a new unbounded queue.
- Retain the **existing non-daemon outbound writer** and one physical FIFO. A stalled stdout writer can still pin process exit; incomplete-writer observation is never treated as borrowed-stdin-only and never permits a fabricated clean return. Owned workers, keyring reads and hooks can also prevent exit. No signal reverts to a forced kill as a hidden timeout policy.
- One retained shielded cleanup job owns workers/adapter/MCP, writer and reader decisions, Redis-last, then the owned Gateway stop. Before Runner closes, observe the owned Gateway stage off the serving loop; outer CLI finally is an idempotent fallback for pre-loop/partial startup and never runs a second physical stop. Do not close Redis/Gateway under workers still able to use them.
- `observe(timeout=10.0)` bounds the full observation, not every stage separately. Emit at most one fixed SHUTDOWN_INCOMPLETE event; retain the same job/handles and DRAINING on expiry. Read Redis's teardown record and actual MCP outcome: a normal serve return is not proof of clean cleanup. Retain the original 300s/default-executor and arbitrary-thread limitations for non-stdio work, without claiming a universal process bound.
- On signal-owned stop, after all non-stdio ownership is actually clean and the only remaining incomplete custody is the borrowed daemon stdin read, main may return **75** after the 10s observation. Record incomplete, not COMPLETE. If any non-daemon writer, provider worker, Redis/MCP owner or close hook is pending, keep the loop/job alive and retain the truthful incomplete observation; no clean exit result is fabricated. This remaining possible hang is explicitly retained with #302/#317/#333.
- Exit mapping proposed for approval: clean EOF **0**; clean SIGINT **130**; clean SIGTERM **143**; completed-but-failed owned cleanup (including nonclean Redis/MCP records) **74**; borrowed-stdio-only signal incompleteness **75**; other incompleteness remains owned with no successful exit. Original startup/configuration failures retain their current error/code. Unrelated cancellation is not converted to success. These numeric choices are agent proposals, not existing operator requirements.
- Atexit emits at most one fixed diagnostic line from the existing record if safe/possible, sharing the once-only incomplete-report flag; it cannot set exit status. It creates no loop/thread/coroutine, starts no cleanup, and performs no blocking wait or new blocking channel. Unregister and restore handlers on orderly exit, including startup failure. No import-time installation.
- POSIX tests use owned children for real SIGINT/SIGTERM/repeated-signal/forced termination. Windows registration/dispatch tests are mandatory; actual owned-console SIGINT delivery is capability-gated by A0, never sent to the user's console. SIGBREAK/CTRL_BREAK is explicitly excluded under #333, not mislabeled SIGINT. Uncatchable forced cases remain qualified. #333's bounded lifecycle is satisfied only as bounded observation here; this does not authorise issue closure or a whole-process termination claim.

### B1. One finite admission policy

Create a small `admission.py` leaf with immutable `AdmissionLimits` and nonblocking count/byte credit accounting, not a new executor/queue framework. Proposed defaults:

| Surface | Limit | Saturation / shutdown disposition |
|---|---:|---|
| ACP pending application queue | 64 items | Immediate pre-turn busy refusal; no parked task per rejected request |
| Active provider-producing work (`session/prompt`) | 8 | Reserve before creating work; parked permission prompts consume this pool |
| Active non-prompt requests | 8, separate | Own FIFO promotion; setters/initialize/session-new never wait behind pending prompts; both classes share64 pending items and the inbound byte account |
| Inbound resident queued + active payloads | 16 MiB | Credits held through request completion; a single message may not exceed8MiB |
| NDJSON/framed body | 8 MiB | Reject/abandon an oversized frame before unbounded accumulation; preserve existing 8192-byte framing header limit |
| Outbound payload slots | 64 ordinary +8 required/control | One FIFO, admission reservation only; never priority-reorder already accepted frames |
| Outbound retained payload bytes | 16 MiB total, of which1MiB reserved for required/control | Normal uses at most15MiB; oversized required work may still fail closed, never block or silently grow |
| Stop marker | one separate reserved slot | Closing never waits for payload capacity; stop/admission decision is atomic |
| Subprocess helper inbound | 64 items /16MiB, max8MiB per frame | Fatal fixed `LiveSessionError` on overflow, never a false live-acceptance pass |
| Subprocess stderr retention | 256KiB total;16KiB maximum whole line +one16KiB gate-rejection cache | Oversized lines are discarded completely while drained; no raw fragment can escape redaction |
| Redis health operation | 2.0s total | Starts before owner admission, includes lock/loop scheduling and ping; expiry requests cancellation and retains owner completion |

Bytes mean UTF-8 serialized payload bytes. Counters are local O(1), constant-cardinality, released exactly once on terminal ownership transitions. A queued payload and its active task share one reservation; do not count it twice or release its bytes merely because it moved out of the queue. Count serialized bytes only; parsed-object/str amplification and bounded serialization/read scratch buffers are explicitly excluded from the byte account. Construct every inventoried physical queue with its declared maxsize (payload capacity + reserved control slots + one stop marker as applicable), not merely external credits. New class-FIFO containers are finite too, share the64 pending credits and do not create another64-request allowance. Update current discovery for put_nowait/get_nowait; historical inventories/replay stay byte-identical. The credits make physical Full unreachable, asserted by focused controls. These are queue/current-work retention bounds, not a cap on all sessions, histories, third-party allocations or process RSS. No tuning/load campaign is needed to prove the finite contract; capacity optimization is separate.

### B2. Control traffic and outbound semantics

- The single reader handles validated, correlated client replies and session cancellation directly on the serving loop; they cannot sit behind a saturated application queue. Unknown replies do not allocate futures; other notifications are ignored today and remain discarded at the reader with a bounded counter; an ignorable notification flood does not terminate the session. Apply no generic priority heuristic to untrusted payload fields.
- Keep FIFO within prompt and non-prompt classes and existing session-busy rules. No duplicate-ID detection exists in NDJSON serving and none is added. Active prompt capacity pauses only prompt promotion; a separate8-slot non-prompt pool keeps config setters/initialize/session-new responsive. Pending non-prompt requests never sit behind pending prompts; one shared64-item/16MiB account bounds both. A single owned scheduler promotes only after a class credit is available, never one waiting task per queued item. Maintain a finite admission record for queued requests; cancel/EOF can retire unallocated requests without starting a turn. session/cancel is keyed by sessionId and retires every unallocated queued prompt for that session present when cancel arrives. Each returns existing non-turn {"stopReason":"cancelled"} using required capacity when deliverable, with no provider/mutation/turn side effect. It does not cancel future prompts not yet admitted.
- If pending-item or resident-byte capacity is exhausted, issue an existing REQUEST_CANCELLED busy response with fixed reason `QUEUE_FULL` using reserved outbound capacity (`message="Server busy"`, `data={"reason":"QUEUE_FULL"}`). No new numeric wire code or automatic retry. If even required/control response capacity is exhausted, abandon the transport and enter the owned stop path; do not silently drop a required message or enqueue an unbounded error response.
- `DedicatedOutboundWriter.submit` must never block an event-loop caller. It atomically reserves capacity and uses put_nowait. Rejected not-started optional progress is SUPPRESSED; rejected required traffic is CONCLUSIVE_FAILURE before any write, with its source future and writer token completed/released exactly once. Serialize exactly once on the producer thread at submit, carry the encoded bytes in OutboundQueueItem and write those bytes without reserialization. Reserve len(encoded); serialization failure is CONCLUSIVE_FAILURE before admission, source future/token finalized or released once. One serialization scratch copy per current producer is outside the retained-queue byte account; producer objects and serialization amplification are not an RSS guarantee. No extra serialization-waiter task/queue is created. Actual write/flush uncertainty remains AMBIGUOUS. Already-started provider work keeps actual settlement facts.
- Required permission/recovery requests, protocol/terminal responses and cancellation/overload responses use the trusted required/control class set by their producer call site. Optional progress uses ordinary capacity. Required/control may use any free ordinary capacity plus its1MiB reserve; ordinary bytes may use at most15MiB. All accepted items retain one physical FIFO. A large required frame that cannot fit the remaining byte budget causes truthful delivery failure/stop; reservations do not guarantee delivery of arbitrary-sized data.
- `request_close` closes admission and places the one reserved stop marker without blocking. It never runs an unbounded join while holding the admission lock. The physical writer drains/finalizes accepted items in FIFO and retains its thread on incomplete close. Batch A's off-loop observation contract stays intact.
- Actual stdio readers use bounded reads, not a length check after an unlimited readline. Preserve injected reader signatures, with an optional limited-read seam for real streams; framed parsing checks Content-Length before body allocation and reads the body in at most64KiB chunks. Oversized framed length closes the transport rather than discarding the attacker-claimed body. NDJSON uses a limited readline/read seam then bounded discard-to-newline, never retaining two oversized buffers. Framed headers may remain one-byte logical reads serviced by the owned daemon reader, not a default-executor thread per byte. Oversize handling emits no raw rejected payload. Shared stdin is not forcibly closed.
- `NdjsonSubprocessSession` overflow is an error flag/terminal record independent of queue space, not a blocking sentinel put. Continue bounded discard/drain or let the caller-owned child teardown proceed; never start another reader. Existing stdout/stderr/transcript consumers see the fatal observation. Keep first usable gate-rejection classification within its bounded cache; if a line cannot be safely retained, use a fixed fallback rather than partial secrets. Its caller-created Popen[str] text streams use character-bounded read/readline chunks; each codepoint takes at most4 UTF-8 bytes. Use at most4096 characters per stderr chunk (<=16KiB encoded scratch), measure encoded length before retaining a whole line, and discard the entire over-budget line. Sanitized expansion must also fit the admitted line/total limits or use a fixed fallback. Class does not acquire permission to kill a borrowed child.

### B3. Health and observability

`RedisRuntime.ping(*, timeout:float=2.0)` observes a single owner submission against one monotonic deadline. The optional `deadline` on owner submission bounds owner-lock admission as well as scheduling, while the existing atomic runtime/owner admission check is preserved. Check the deadline again on the owner loop before invoking the operation factory; an expired/unstarted operation never starts late. Use concurrent.futures.wait doneness (as close already does), not future.result(timeout), to identify expiry separately from an operation-raised builtin TimeoutError. Observation expiry raises RedisHealthDeadlineExceeded(ConnectionError) defined in runtime.py, preserving existing caller ConnectionError handling without new external edits. The deadline pre-entry check lives in _OwnerOperation._drive beside pre-start cancellation. Owner-lock admission uses Lock.acquire(timeout=remaining) only on the deadline path. On expiry request owner-task cancellation without destroying its separate completion signal. The owner retains and consumes the late result/failure; a late success never changes the timed-out caller's verdict. Keep existing ConnectionError mapping and distinguish an observation deadline from a completed operation that itself raised TimeoutError. Do not change all run_sync callers or pretend a socket-connect timeout is an operation deadline.

Emit fixed, bounded lifecycle/admission diagnostics through existing channels: queue identifier, counts/bytes, fixed rejection/close outcome and monotonic wait duration. No raw methods/params/paths, credentials, exception text or raw payload fingerprints. Use one event per full/recovered/closing transition plus counters, not one log per rejected frame. Preserve exactly-once cost/audit receipts; telemetry backpressure never turns unknown charged work into zero cost. Queue-full diagnostics must not use _pre_run_refused/PRE_RUN_REFUSAL_REASONS: no debug_trace.py production-policy change is admitted. Use fixed lifecycle/admission diagnostics and existing safe reporting channels. New acp_debug_log sites require the admitted classified-site inventory update. New literal call sites get explained logging-audit entries; no scanner/guard bypass or frozen audit regeneration.
